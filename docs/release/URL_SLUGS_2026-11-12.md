## Deployment (live database = source of truth)

1. Back up the live database.
2. Deploy the code.
3. `wp eval-file dev/tools/content/url-slugs-20261112.php dry-run`: check the list, then run it without `dry-run`.
4. Check: an old URL returns 301 to the new one; the header menu links and event order are correct; `wp yoast index` if the Yoast sitemaps still show old URLs.
5. If the site is already indexed: submit the sitemap in Search Console. Update any external links you control (Google Business Profile, social profiles, ads) to the new URLs.

## Singular event names (owner, 2026-11-13)

Events are named in the singular: **Birthday, Wedding, Graduation Party, Prom, Corporate Event, Anniversary**. URLs follow: `wedding-…`, `prom-…`, `corporate-event-ice-cream-catering` (table above). The URL tool now accepts several old slugs per event (the original live slug and the plural slug used locally on 2026-11-12), so live goes straight to the singular URL and every old address 301s in one hop.

- `dev/tools/content/event-names-20261113.php` (dry run, report, compare-and-set; edits made in wp-admin are reported "kept"): event titles, short labels ("Graduation" → "Graduation Party", "Corporate" → "Corporate Event"; quote tiles, inquiry summaries and emails), menu item titles in every menu, and the Service Areas occasions intro. Historical inquiries are not touched (they store keys).
- Not changed: event keys, quote context (`?event=wedding`), search titles (already singular, e.g. "Wedding Ice Cream Catering"), and prose such as "for birthdays, weddings and parties" in descriptions and blog text.
- Live order: after step 3 above, run `wp eval-file dev/tools/content/event-names-20261113.php dry-run report=/path/names-dry.json`, review any **kept** line, then run it without `dry-run`; `wp yoast index`; purge caches.
- Local (2026-11-13): backup `C:\laragonackup\catericecream\pre-event-names-20261113-003512\`; URL tool renamed 3 slugs, 3 menu links, 2 blog drafts; names tool set 15; both re-runs no-ops. Verified: all nine old event addresses (original and plural) → one 301; six new pages 200 with singular breadcrumbs; header menu and quote tiles singular; no plural event name on Home, Events, Treats, Service Areas, Get a Quote, Contact or event/treat pages.

Rollback: restore the backup, or rename the slugs back in wp-admin (WordPress then redirects the new URLs to the old ones) and fix the custom menu links.

## City pages (owner approved 2026-11-12)

`/service-areas/{state}/{city}/` → `/service-areas/{state}/{city}-ice-cream-catering/` (e.g. `/service-areas/california/academy-hills-ice-cream-catering/`). State hubs (`/service-areas/california/`) and the Service Areas page are unchanged.

- **Code only, no data change.** Stored city slugs, city keys (`pasadena-ca`), aliases and slug history are unchanged. `DatabaseRepository::URL_SUFFIX` is appended by `DatabaseRepository::url()` (the single source for city links, canonicals, Yoast metadata, the location sitemap, previews, Cities We Serve and the map) and stripped by `Routes::resolve()`.
- The bare old address, aliases and previous slugs (with or without the suffix) 301 in one hop to the suffixed canonical; query strings are kept. Rewrite rules are unchanged (no `ROUTE_VERSION` bump).
- Admin: Add City shows the suffixed public address; the URL slug field still holds the plain slug (do not type the suffix).
- Files: `src/Locations/DatabaseRepository.php`, `src/Locations/Routes.php`, `src/Locations/Admin/LocationsPage.php`; tests in phase05, service-areas, seo-20261028, qa-20261026, phase06, phase09.
- Deployment: after the code, run `wp cic locations flush-cache` (cached lists hold the old URLs), then `wp yoast index`, and check one old and one new city URL.
