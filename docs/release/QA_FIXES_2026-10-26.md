## 4. Live checks for the form failure (item 3)

Run these in order and keep the results; they distinguish a hosting block from a site error without changing anything.

1. **Records first.** wp-admin → Enquiries: look for inquiries created at the audit times (Incomplete and Submitted) and the operator mailbox for matching notifications. A timed-out request may have saved an inquiry and sent mail even though the browser showed the error.
2. **No-side-effect request from a terminal** (does not create an inquiry or send mail):
   `curl -s -o - -w "\nHTTP %{http_code}\n" -X POST https://www.catericecream.com/wp-json/contact-form-7/v1/contact-forms/358/feedback`
   Expected from WordPress: a small JSON error from Contact Form 7 (HTTP 400-ish, e.g. about a missing unit tag). An HTML page, `sgcaptcha`, `.well-known/sgcaptcha`, HTTP 202/403/429 means the hosting security layer answered instead of WordPress.
3. **Browser check with DevTools** (normal browser, not the audit browser): F12 → Network → submit the Contact form once with a clearly labeled test message to your own address (delete the inquiry afterwards). Record for `…/contact-forms/358/feedback`: status code, response type (JSON or HTML), time taken. JSON with `"status":"mail_sent"` and `"cic":{"accepted":true}` = working.
4. **If HTML/202/403/429:** SiteGround Site Tools → Security → (Blocked Traffic / AI anti-bot logs) for that time and IP; ask SiteGround support to review the false positive for POST requests to `/wp-json/contact-form-7/v1/contact-forms/*/feedback`. Do not disable the protection wholesale.
5. **If HTTP 500:** Site Tools → Statistics → Error Log (and `wp-content/debug.log` if enabled) for PHP fatal errors at that time; send the error lines.
6. **If it takes more than ~25 s:** the request is slow on the server (the inquiry is saved before emails are sent, so check mail delivery/SMTP timing); send the timing and the mail settings (not passwords).

With the fixed `quote.js`, a visitor whose request is blocked by a security page now sees "Your request didn’t go through … call us at 424-235-4942" instead of "couldn’t reach the server".
