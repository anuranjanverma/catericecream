## 4. Indexing and sitemap rules

- **Environment:** only `production` can be indexable; local, development and staging are always `noindex, nofollow` (unchanged). Production also needs Reading → "Discourage search engines" **off**.
- **Indexable:** Home, Events archive + six events, Treats + four treats, Service Areas, California directory, About, Contact, clean Get a Quote; cities only when published + Index + reviewed content + ≥1 enabled production ZIP.
- **noindex, follow:** any query-string variant of Get a Quote, Contact, Service Areas and the state directory (prefills, receipts, filters, paging); unreviewed/unserved cities; previews; search results; 404s; category/tag archives.
- **Tracking parameters** (`utm_*`) on other pages: indexable, canonical = clean URL (Yoast).
- **Not reachable:** author archives (redirect home), date archives (404), sample post (Draft → 404), cart/checkout/account (302 → Treats, guard), product category/brand (301, guard), unknown or excluded city/state routes (404; Compton has no published route).
- **Sitemaps** (`/sitemap_index.xml`): page, product, cic_event and `cic-locations-sitemap.xml`. Excluded: Woo utility pages, the duplicate shop page, sample/blog/taxonomy/author sitemaps. Locations: state directory + eligible cities only, `lastmod` from the city record / reviewed content (not per request). ~200 cities fit one file (limit 50,000 / Yoast default 1,000 per file), so no chunking is needed. Yoast's sitemap transient cache is off by default, so every request is current; every location write and city-content save bumps the location cache. Sitemap inclusion does not guarantee indexing.

## 5. Dynamic location SEO (how it works)

1. `Routes::current()` resolves `/service-areas/{state}/{city}/` against the database (published only; aliases redirect; unknown → 404).
2. `ViewModel::city()` builds title/description from the city's own fields, else the Service Areas city template with `{city}` tokens and the repository label ("Los Angeles, CA"); never claims every ZIP is served. Memoised per city key, so no route can reuse another route's values.
3. `Seo\Service::context()` adds `noindex` unless `DatabaseRepository::is_indexable()` (published + Index + reviewed + served); previews and query strings are always noindex.
4. `YoastAdapter` registers its filters per request with that context only: title, description, canonical, OG/Twitter, image, WebPage + BreadcrumbList + Service (areaServed City, provider #organization).
5. Sitemap: `indexable_entries()` (cached under the location cache version) → `cic-locations-sitemap.xml`.
